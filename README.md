# NAC Mac

使用 Swift / SwiftUI 开发的 macOS 网络准入认证助手，应用显示名称为 **NAC 小助手**。当前为联调版本。

## 当前功能

- 菜单栏常驻与桌面控制台；窗口打开时显示 Dock 图标并支持 Command-Tab，关闭后仅保留菜单栏。
- 读取服务器配置、查询并复用现有设备登记，手动提交账号密码认证。
- 认证完成后自动建立连续 TCP 心跳连接；首次匹配应答后显示“连接正常”，断开后显示“连接中断”。
- 设备记录状态独立显示；待审核、需注册或需额外认证时不自动连接。诊断面板保留单次心跳与状态查询。
- 可查看当前 Mac 的名称、型号、系统和活动 IPv4 网卡，以及最近查询的服务器设备登记资料。
- 可选记住密码：认证完成后保存在本机钥匙串，按服务器和账号隔离，不写入偏好设置；令牌和 Cookie 仅保留在进程内存中。
- 支持使用已保存密码重新登录并入网；已移除验证码界面入口。

2026-11-03 用户报告连续收到 44 次心跳应答、约 21 分钟网络正常。该结果只覆盖本次公司内网环境；此前两客户端同时运行出现连接关闭，因果关系尚未完全确认。

## 构建与运行

需要 macOS 15 或更新版本，以及提供对应 SDK 的 Xcode / 命令行工具。使用系统 Swift 编译器，无第三方 Swift 依赖。

```sh
bash app/build-preview.sh
open "local/NAC Preview.app"
```

在“服务器设置”中填写实际认证服务器地址，再检查服务器并手动登录。源码不包含公司服务器地址，文档中的 `192.0.2.10` 仅为示例地址。有效的服务器地址会在检查时保存在本机偏好设置，重启后自动填入；账号密码和设备身份不随之保存。

## 安装用 app

```sh
bash app/build-app.sh
```

生成 `local/NAC 小助手-0.13.5.app`（当前版本 0.13.5），可复制到 `~/Applications`。脚本使用当前 Mac 架构编译优化版本，生成 Finder / Dock 图标并进行 ad-hoc 本机签名验证；没有 Developer ID 签名或公证，不作为跨机器发行包。

打包输出已存在时脚本会停止，请先移走旧的本地打包输出再重新构建。不要覆盖正在运行的应用。测试安装版前先退出旧预览版和原客户端，再手动设置服务器、登录并开启心跳；初次运行不自动连接。

## 验证

```sh
bash app/check-protocol.sh
python3 app/check-heartbeat-transport.py
bash app/check-model.sh
```

第一项为 16 项离线协议检查；第二项为 8 种本机回环连接测试；第三项验证服务器检查、偏好设置、认证后自动连接和断连/重连的状态转换，均不访问真实认证服务器。`app/Checks/` 中另有明确传入服务器地址才执行的内网诊断入口，未包含在上述离线检查中。

## 限制

SPA 登录后交接、完整策略处理、VPN、多因素认证、睡眠唤醒及断网恢复尚未完整接通或验证。心跳断开后不会自动重连或重新提交密码。设备在线和账号认证被受理不等于全部网络准入步骤已完成；保留原客户端作为备用。

当前兼容流程依赖服务器已有设备记录，不提交新设备登记。设备报告准备脚本只生成本地待审文件，不发送请求，运行时必须显式提供 `--server`。

## 目录和版本控制

- `app/`：应用源码、构建脚本与检查入口。
- `docs/`：协议调查记录及边界说明；早期条目保留当时的进度，以最新条目为准。
- `local/`：构建产物、本机配置及原始分析证据，被 Git 忽略，不随仓库发布。

不提交账号密码、令牌、设备标识、服务器原始响应、第三方应用或逆向分析数据库。源码和文档不包含原版应用分发包。

详细行为见 [app/README.md](app/README.md)，调查记录见 [docs/protocol-notes.md](docs/protocol-notes.md)。

新设备注册的静态分析与实现顺序见 [注册流程说明](docs/registration-flow.md)。当前 app 尚未开放新设备注册提交。

登录后的自动连接行为与状态定义见 [连接状态说明](docs/connection-states.md)。

本地诊断日志的位置、保留规则及下午断线排查方法见 [诊断日志](docs/diagnostic-logging.md)。日志不会自动上传。
