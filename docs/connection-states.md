# 认证后自动连接与连接状态

版本：0.9.0。设备记录、账号认证和本应用心跳是不同证据，统一状态由本应用的实际流程推进。

| 事件 | 连接状态 | 后续动作 |
| --- | --- | --- |
| 启动或改变服务器 | 未登录 | 恢复服务器地址，不自动认证。 |
| 检查配置和设备记录 | 检查中 | 只读查询，完成后仍为未登录。 |
| 用户提交凭据 | 认证中 | 单次认证，立即清空密码输入框。 |
| 服务器仍要求改密、MFA、绑定、登记、审核、SPA/VPN 等后续步骤 | 待完成认证 | 显示服务结果，不启动心跳。 |
| 认证流程受理且无已识别后续要求 | 正在连接 | 自动创建一条连续心跳连接。 |
| 收到本应用序列号和 XML 校验通过的心跳应答 | 连接正常 | 继续按发送时钟每 30 秒保活。 |
| 心跳超时、远端关闭、异常帧或未支持的消息 | 连接中断 | 停止；不自动重登或循环重连。 |
| 用户停止心跳 | 已停止保活 | 保留当前进程认证上下文，可手动重新连接。 |

“连接正常”表示当前应用的心跳传输已确认；网络资源访问仍取决于服务器下发的权限。服务器设备记录显示在线，不会单独把连接状态改为正常。单次诊断的应答也不会被当作持续连接。

## 登记状态保护

登录响应的 Registered 优先于查询时的记录：1 为当前方言已登记值；0 为待审核；-1/-2 需要登记；缺失时回退到已查询记录，未知值不自动连接。响应的空值不会回退成已登记。原有改密、多因素、账号绑定、SPA/VPN 提示继续保留。

## 并发与取消

登录、检查和心跳各有独立代际标识。改变服务器或重新检查时，旧登录结果不能为旧服务器偷偷开启连接；停止或重新连接后，旧心跳应答、失败与取消回调不能覆盖当前状态。重复调用开启连接不会创建第二条并行心跳。

## 验证及边界

- `bash app/check-model.sh`：以模拟服务和模拟心跳检查成功、后续认证、失败、重复点击、远端关闭、重连以及旧回调，不访问真实认证服务器。
- `bash app/check-protocol.sh`：14 项离线协议检查，含登记状态的响应优先级。
- `python3 app/check-heartbeat-transport.py`：8 项本机回环测试，覆盖真实传输的连续应答、RoleChanged、关闭、异常帧、超时与取消。
- 离线模拟界面用于核对“连接正常”和“设备记录”分开显示，未替代实际账号登录测试。

睡眠、网卡切换、离开内网及回到内网后的恢复尚未完整验证。本版本不自动重新提交密码，不保存密码，也不执行尚未实现的设备登记和策略流程。
