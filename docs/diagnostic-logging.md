# 本地诊断日志（0.13.0）

用途：对比下午断线前后的认证、心跳、睡眠/唤醒和网络变化，区分现象；单凭客户端日志不能证明服务端策略就是根因。

## 记录内容

- 每行包含带时区偏移的时间戳、随机应用会话标识、实际应用版本和事件类型。
- 认证和设备查询：固定接口类别、HTTP 状态、数字结果码、URL 错误码、耗时；不保存 URL、表单、响应正文或服务器自由文本说明。
- 心跳：启动模式、TCP 建立、发送序号、应答次数及延迟、结束阶段和运行时长。结束原因区分完成、取消、超时、服务端 EOF、连接/收发错误、未知消息、帧和 XML 校验失败。
- 系统：睡眠、唤醒、会话活跃/非活跃；网络可用性、接口类型及昂贵网络标志。只观察本地系统回调，不增加认证探测或重连。
- 用户点击重新登录和登录结果，帮助比较恢复前后的变化；失败/结果描述使用固定分类。

所有动态日志字段受白名单或数值校验限制。不记录账号、密码、令牌、Cookie、设备 ID、MAC、IP、SSID、文件清单、完整报文、原始服务端提示或钥匙串内容。原始信息仍只在已有内存处理流程中使用。

## 位置、容量与操作

日志位于 `~/Library/Logs/NACMac/`，采用 JSONL，每日一个主文件。保留最近 7 个自然日，每个文件上限 2 MiB，另保留当天一份轮转文件，总量通常不超过约 28 MiB。文件为 0600，目录新建为 0700。应用后台串行写入，写入错误不阻断认证或心跳；打开目录时会提示不可用。

菜单面板增加“打开日志”和“清除日志”。清除需确认，只删除此功能管理的日志文件，不删除无关文件或凭据，不影响连接；之后的事件继续记录。日志不自动上传。

## 下午断线时怎么做

1. 留意大概发生时间，先不要清除日志。
2. 按正常方式重新登录恢复网络，不必为了采集而维持断网。
3. 后续查看断开前后的心跳结束原因、最近应答、系统和网络事件，以及重新认证结果码。

例如：若正常心跳后出现 remote_closed，同时没有睡眠或网络不可用记录，服务端或中间网络设备关闭会话是候选解释；仍须结合服务端记录才能确认。若先出现 sleep/wake、路径不可用或网络错误，则应先排查本机网络或休眠恢复。

## 验证

`DiagnosticLogCheck` 验证字段脱敏、JSONL、轮转、保留期、清除保留无关文件、恢复写入及日志目录故障隔离。8 项回环传输检查额外核对每次结束原因、应答计数和无设备标识/令牌泄漏。普通命令行模型/协议检查默认关闭生产日志；日志单元和回环检查使用临时目录。尚待实际下午场景采集。
